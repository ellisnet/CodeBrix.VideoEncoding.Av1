================================================================================
av1-native-tools/aom and av1-native-tools/nasm - VENDORED UPSTREAM SOURCE
================================================================================

WHAT THESE FOLDERS ARE
--------------------------------------------------------------------------------
Unmodified copies of two official upstream release tarballs:

  aom/    libaom 3.15.2 - the Alliance for Open Media's AV1 reference codec. The
          ONLY upstream source the shipped codebrix_av1 native library is built
          from (encoder side only).
  nasm/   nasm 2.16.03 - the Netwide Assembler. A BUILD-TIME TOOL ONLY: it
          assembles libaom's x86-64 SIMD on the Linux x64 and Android x64
          builds. It is never shipped, never linked, and its licence is not
          part of LICENSE-Aom.txt.

No build step in this repository clones, downloads, or otherwise fetches either
(or anything else) at build time - see README.txt for the rule this exists to
satisfy. The release tarballs themselves are kept, byte for byte as downloaded,
in upstream-downloads/, so the vendored trees can be re-verified at any time
with no network.

This file lives BESIDE the trees, not inside them, so that aom/ and nasm/ stay
byte-identical to their tarballs (not even an added file).

LICENSING OF libaom - WHAT IS AND IS NOT BUILT
--------------------------------------------------------------------------------
libaom is BSD-2-Clause (aom/LICENSE, "Copyright (c) 2016, Alliance for Open
Media") plus the Alliance for Open Media Patent License 1.0 (aom/PATENTS).

Compiled into codebrix_av1 (shim/CMakeLists.txt drives libaom's own CMake):
the encoder side of aom/ (aom/, aom_dsp/, aom_mem/, aom_ports/, aom_scale/,
aom_util/, av1/ - common + encoder, and common/args_helper.c), plus exactly
two third_party components:
  third_party/fastfeat   BSD-3-Clause (Edward Rosten) - FAST corner detector
                         (the encoder's global-motion search)
  third_party/vector     MIT (Peter Goldsborough)
and, on the x86-64 RIDs only, the assembly framework
  third_party/x86inc     ISC (x264 project) - %include'd by libaom's .asm files
Their licence texts are composed into LICENSE-Aom.txt
(licenses/compose-license-aom.sh; its --check re-runs a survey of every
copyright line in the compilable sources on every bash build, and every gate
checks that the only third_party objects in a build are fastfeat's and
vector's).

Vendored but NEVER compiled and NEVER shipped (they are part of the tarball):
  the AV1 DECODER (CONFIG_AV1_DECODER=0), apps/ (aomenc, aomdec), examples/,
  tools/, stats/, test/ (unit tests + test vectors' scripts), doc/,
  third_party/googletest, third_party/libwebm (CONFIG_WEBM_IO=0),
  third_party/libyuv (CONFIG_LIBYUV=0 - the shim never scales or converts),
  third_party/highway (CONFIG_HIGHWAY=0, libaom's default).

Used here      : libaom's own CMake (shim/CMakeLists.txt add_subdirectory,
                 EXCLUDE_FROM_ALL). Perl runs libaom's rtcd.pl / version.pl at
                 configure time; every generated file (config/aom_config.h,
                 aom_version.h, the *_rtcd.h headers) goes into the BUILD tree,
                 never into aom/. The version string comes from aom/CHANGELOG
                 (GIT_EXECUTABLE is deliberately a non-existent path), so
                 aom_codec_version_str() returns "v3.15.2" on every machine.

How it is used : build-nasm.sh copies nasm/ to a scratch folder and runs its
                 own ./configure + make there (the vendored tree is never
                 written): inside the manylinux x86_64 container for linux-x64
                 (the image has only yasm 1.3.0, which libaom treats as the
                 lesser assembler and which is never used), and on the build
                 host into output/host-tools/bin for android-x64 and the host
                 build. arm64 / riscv64 assemble nothing (NEON is C intrinsics,
                 RISC-V is C + RVV intrinsics). Windows and macOS use the
                 machine's own nasm (as the dav1d builds do).

NOT MODIFIED
--------------------------------------------------------------------------------
No file in aom/ or nasm/ has been modified, renamed, reformatted, added or
deleted, and none ever should be. Verified on 2026-10-10 with the check below
(no differences; 1520 files in aom/, 1190 in nasm/).

If a future build ever needs a change to either source, it goes in
patches/*.patch and is applied by the build scripts into a scratch copy at build
time, never into these folders. As of 2026-10-10 there are no patches.

COMMITTING aom/ (once): aom/.gitignore lists ".gitignore" itself, and a nested
.gitignore wins over ours, so git skips that one file. Add it explicitly once:
    git add -f av1-native-tools/aom/.gitignore
(once tracked, it stays tracked). Nothing else in either tree is ignored -
av1-native-tools/.gitignore re-includes everything the repository-root
.gitignore would otherwise hide. Check with:
    git ls-files --others --ignored --exclude-standard av1-native-tools/aom av1-native-tools/nasm

VERIFYING THE SNAPSHOTS AGAINST THEIR TARBALLS (no network needed)
--------------------------------------------------------------------------------
    cd av1-native-tools
    sha256sum upstream-downloads/libaom-3.15.2.tar.gz upstream-downloads/nasm-2.16.03.tar.xz
    mkdir /tmp/aom-verify /tmp/nasm-verify
    tar -xzf upstream-downloads/libaom-3.15.2.tar.gz -C /tmp/aom-verify
    tar -xJf upstream-downloads/nasm-2.16.03.tar.xz  -C /tmp/nasm-verify
    diff -r /tmp/aom-verify/libaom-3.15.2 aom        # expect no output
    diff -r /tmp/nasm-verify/nasm-2.16.03 nasm       # expect no output
